# ANCAP LIFE

A multiplayer business simulation played on a 3D model of the real Earth. Every player shares one map and one clock: start with a street food cart, lease your first shop, then buy buildings and land, build on empty plots, mine resources, run a corporation, float it on the player stock market, and branch out into roads, telecoms, VPNs and private security.

Live at **https://ancaplife.vercel.app**

## How it is built

- **One static page.** The whole game is `index.html` (three.js r128 for the 3D world, plain JavaScript, no build step). It is made of a core plus feature "layers", each an IIFE in its own `<script>` block (panels, estate, ventures, carts, dock, etc.).
- **Map data** lives in `data/`: world outlines and place names, coarse detail tiles (`data/tiles/`), and real street and building footprints for featured cities (`city_*.json`, built from OpenStreetMap by `tools/build_city.py`).
- **Accounts and the shared world** use [Supabase](https://supabase.com) (auth + Postgres with row-level security + realtime). The browser only ever uses the public anon key.
- **Hosting** is Vercel, serving the repo as static files (`vercel.json` sets caching for `data/`).

## Running it locally

```sh
python3 -m http.server 8000
# then open http://localhost:8000
```

Any static file server works. Without a Supabase project the game still runs, with saves kept in the browser only.

## Setting up the database

Everything the server needs is in `supabase/`:

| Path | What it is |
|---|---|
| `supabase/migrations/0001…0010_*.sql` | The schema, in order: profiles and saves, players and map claims, the resource exchange, world chat, the stock market and league, account features, resets and clean-up, the locked-down leaderboard, save versions and backups, chat moderation. |
| `supabase/schema.sql` | All migrations in one file, generated by `supabase/build-schema.sh`. |
| `supabase/ops/` | One-off maintenance scripts that are not part of the schema. |
| `supabase/test/` | A stand-in for Supabase's `auth` schema and a test script, for checking the migrations on plain Postgres. |

For a new project: create it, then paste `supabase/schema.sql` into **SQL Editor → New query** and run it. Every migration is safe to run more than once, so running the whole file on an existing project brings it up to date.

Then in the dashboard:

- **Authentication → Sign In / Providers → Email**: turn off "Confirm email" (sign-up checks are done by the `handle_new_user` trigger), and turn off anonymous sign-ins.
- Put the project URL and anon key into `SB_URL` and `SB_KEY` near the top of the accounts section of `index.html`. Never put the service-role key in the page.

### Testing the migrations

With a local Postgres 15+:

```sh
createdb ancap_test
psql -d ancap_test -f supabase/test/supabase_stub.sql
psql -d ancap_test -f supabase/schema.sql
psql -d ancap_test -f supabase/test/run_tests.sql
```

The test script signs in as several fake players and checks that direct writes to the leaderboard are refused, oversized net worth is capped, other players' claims can't be changed, stale and downgraded saves are refused, backups restore, and the chat filter, reports, mutes and blocks work.

## What the server enforces

- **Leaderboard.** Players can read every `players` row but write none. The game calls `submit_player`, `submit_league`, `add_loyalty`, `set_avatar` and `claim_referral_trophies`. These cap net-worth growth to what a very successful company could earn, work out the weekly league baseline and referral trophies on the server, and only unlock avatar skins at the right loyalty.
- **Saves.** One row per account with a format version, a revision counter and a last-known-good backup (rotated at most every 10 minutes). Saves from a device that is behind, or from an older game version, are refused. `restore_my_backup()` swaps the current save and the backup. The game also keeps a local backup copy and upgrades old saves step by step (`SAVE_V` and `SAVE_MIG` in `index.html`).
- **Chat.** Rate limits, a word filter (masks swearing, blocks slurs), reports (three reports hide a message), automatic 24-hour mutes for repeat offenders, and server-side blocks.
- **Accounts.** Minimum age 13, checked at sign-up. Players can download their data and delete their account themselves from **Account → Privacy & data**.
